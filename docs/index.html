    01  Not just four colours

    The whole palette, and your own.

    Colours resolve to Nova’s own --colors-* variables, so any Tailwind family and shade works — and re-theming Nova re-themes every indicator. Literal CSS colours and explicit light/dark pairs are first-class too.

    Four ways to name a colour
    NovaFieldIndicator::make('Status')->colors([
    'active'   => 'success',        // a semantic token
    'archived' => 'emerald-600',    // any family and shade
    'brand'    => '#7c3aed',        // a literal
    'custom'   => ['light' => 'violet-600', 'dark' => 'violet-400'],
]),

    Rendered

    active archived brand custom

    Switch the theme in the masthead — the first, second and fourth shift shade; the literal deliberately does not.

    02  Four shapes, three sizes

    A shape can carry meaning too.

    Colour alone fails about one man in twelve, and fails everyone in a greyscale print. A distinct shape per state is one of the three ways this package lets you avoid relying on it.

    Shapes
    NovaFieldIndicator::make('Status')->dot(),
NovaFieldIndicator::make('Status')->ring(),
NovaFieldIndicator::make('Status')->square(),
NovaFieldIndicator::make('Status')->pill(),

// and a state that is still happening
NovaFieldIndicator::make('Status')->states([
    'syncing' => ['label' => 'Syncing', 'color' => 'sky-400', 'pulse' => true],

    03  Resolved on the server

    An index row carries a result, not a rulebook.

    Version 2 pushed the whole label and colour configuration into every row of an index and looked it up again in the browser. A six-state field on fifty rows shipped its maps fifty times. Resolution now happens once per value, in PHP.

    2.x — per row
    // repeated on all 50 rows
{
  "labels": { "active": "Active", "banned": "Banned", /* … */ },
  "colors": { "active": "success", "banned": "danger", /* … */ },
  "unknownLabel": "Unknown",
  "withoutLabels": false
}
    3.0 — per row
    {
  "indicators": [{
    "value": "active",
    "label": "Active",
    "ariaLabel": "Active",
    "color": { "light": "rgba(var(--colors-green-500))", /* … */ },
    "icon": null, "pulse": false
  }],
  "shape": "dot", "size": "md"
}
    A side effect worth naming. Because the browser no longer inspects a colour string, colour literals are validated once, server-side, against an anchored allow-list. The 2.x client-side regex was unanchored and would have accepted #fff; background-image:url(…).

    Honest comparison

    When not to reach for this.

    Nova already ships Badge, and for four hard-coded states it is the right answer — it is built in, it needs no dependency, and ->map() covers a surprising amount. If success, info, danger and warning are all you need, use it and stop reading.

    Use Badge

    Four states, default styling, no colour of your own, and no need for a filter or an icon. Fewer moving parts wins.

    Use this package

    States come from an enum, you want a specific shade, you need dark mode to be right, or colour must not be the only channel.

    Use neither

    If the value is editable, it is a Select. This field is Unfillable by contract and never writes.

      Guide

      Everything the field can do, in the order you are likely to need it.

      Labels, colours and icons

      Each value gets a state. Configure the parts separately, or all at once with states() — they write to the same table.

      Separately
      NovaFieldIndicator::make('Status')
    ->labels(['active' => 'Active', 'banned' => 'Banned'])
    ->colors(['active' => 'success', 'banned' => 'danger'])
    ->icons(['active' => 'check-circle', 'banned' => 'x-circle']),
      Or together
      NovaFieldIndicator::make('Status')->states([
    'active' => [
        'label'   => 'Active',
        'color'   => 'success',
        'icon'    => 'check-circle',
        'tooltip' => 'Account is active',
    ],
    'syncing' => ['label' => 'Syncing', 'color' => 'sky-400', 'pulse' => true],
]),

      Calling icons() turns icons on by itself. Icons are heroicons rendered by Nova’s own component, so they add nothing to this package’s bundle.

      Enum-first

      The shortest path. Implement one, two or all three contracts on an enum you already have; anything you leave out falls back sensibly.

      app/Enums/Status.php
      use Gabrielesbaiz\NovaFieldIndicator\Contracts\{HasColor, HasIcon, HasLabel};
use Gabrielesbaiz\NovaFieldIndicator\Enums\Color;

enum Status: string implements HasColor, HasIcon, HasLabel
{
    case Active = 'active';
    case Banned = 'banned';

    public function indicatorLabel(): ?string
    {
        return match ($this) {
            self::Active => 'Active',
            self::Banned => 'Banned',
        };
    }

    public function indicatorColor(): Color|string|array|null
    {
        return match ($this) {
            self::Active => Color::Success,
            self::Banned => 'danger',
        };
    }

    public function indicatorIcon(): ?string
    {
        return match ($this) {
            self::Active => 'check-circle',
            self::Banned => 'x-circle',
        };
    }
}

      The methods are named indicator* rather than getLabel() so an enum can implement Filament’s contracts and these side by side without a clash.

      You may not need ->enum() at all. If the attribute is cast to this enum, the field detects it from the value and derives the table itself — NovaFieldIndicator::make('Status') is enough. The derived table is memoised per enum class, so fifty rows cost one pass over cases().

      An enum implementing none of the contracts still works: case names are humanised, so InReview becomes “In review”.

      Shapes and sizes

      Appearance
      ->dot()  ->ring()  ->square()  ->pill()
->shape(Shape::Ring)        // or the enum
->size('sm')                // sm | md | lg
->withoutLabel()            // the mark only, no text
->pulse()

      Measurements live in the stylesheet, so the payload carries a token rather than pixels and a new size never changes the wire format.

      Continuous values

      A state table cannot enumerate a percentage. ranges() takes inclusive lower bounds and sorts them itself, so declaration order does not matter.

      Health score
      NovaFieldIndicator::make('Health')->ranges([
    0  => 'danger',
    50 => 'warning',
    80 => 'success',
]),

// or with labels per band
->ranges([
    0  => ['label' => 'Critical', 'color' => 'danger'],
    50 => ['label' => 'Healthy',  'color' => 'success'],
])

      A non-numeric value skips the table entirely and falls back to the default colour.

      Hiding values

      Visibility
      ->hideWhen('active')                    // one value
->hideWhen(['invited', 'requested'])     // several
->hideWhen(fn ($value) => $value === 'inactive')
->hideWhenEmpty()                       // null, false, 0, '' and '0'

      A hidden field short-circuits: nothing is resolved for it at all, so the cost is not paid per row.

      One behaviour change worth knowing. In 2.x a string argument was tested with is_callable() first, so shouldHide('trim') silently invoked trim() as the predicate. hideWhen() dispatches on the declared type, so a string is always a value. Pass a closure if you wanted a callback.

      Filtering

      Call filterable() and the field builds its own select-filter options from the state table, or from the enum when there is one.

      Filterable
      NovaFieldIndicator::make('Status')->enum(Status::class)->filterable(),

      If there is nothing to offer — a field configured only with colorUsing(), say — no filter is registered, rather than an empty dropdown.

      Accessibility

      WCAG 1.4.1 says colour must not be the only visual means of conveying information. About one man in twelve has some form of colour vision deficiency, and a greyscale print has none at all. This package gives you three channels and uses the first by default:

      1. A visible label — on by default. The text is the meaning; the mark reinforces it.
      2. A distinct icon per state, via withIcons().
      3. A distinct shape per state — a ring for pending, a square for queued.

      For screen readers the field switches behaviour based on whether text is visible, because the two cases need opposite treatment:

      CaseMarkupWhy
      Label visiblemark is aria-hidden The text is already the accessible name. An aria-label here would override the visible text and break voice control.
      withoutLabel()role="img" + aria-label Colour alone carries the meaning, so the mark becomes a named graphic. The label is never empty.

      Icons are always aria-hidden; they are a redundant channel for sighted users, never the name. The pulse animation is wrapped in prefers-reduced-motion, and forced-colors mode keeps the mark visible with a CanvasText border.

        Colours

        How a colour is named, how it is resolved, and why it survives a theme change.

        Nova’s palette, not ours

        Nova emits every Tailwind colour at :root as --colors-<family>-<shade>, holding the channels only — 34, 197, 94 rather than a finished colour. A token resolves to a family and two shades, and is used as rgba(var(--colors-green-500)).

        That indirection is the whole point: an application that re-themes Nova re-themes every indicator, with no CSS of its own. Version 2 hard-coded fifteen Tailwind v1 hex values, which could not follow a theme and could not express a dark variant.

        Dark mode is a shade change, not a colour change. Nova’s palette variables are not semantic — --colors-green-500 is the same value in both themes. So the field resolves two values and the stylesheet picks one, generally one step lighter in dark mode, because a 500 mark on a slate-800 surface reads dimmer than on white.

        The built-in tokens

        Nine names, resolved for you. The first four are the ones that rendered invisibly in 2.x.

        Every accepted form

        Resolution is ordered. The first rule that matches wins.

        #FormExampleNotes
        1Color caseColor::SuccessThe typed form.
        2Application token'brand'From config. Checked first, so it can shadow anything below.
        3Built-in token'success'The nine names above.
        4Family and shade'emerald-600'Any Nova family, shades 50–950.
        5Bare family'emerald'Uses the configured default shades.
        6Explicit pair['light' => …, 'dark' => …]Each side resolved on its own.
        7Literal CSS'#7c3aed'Allow-listed. Same in both themes unless paired.
        8Anything else—Throws at field-definition time.
        An unknown value never throws. A row whose status is missing from the state table is data, not a bug: it falls back to the default colour and unknown() label. Only an unknown token spelling throws, because that is a typo in your resource and you want to hear about it immediately. Nova’s own Badge throws for both.

        Literals are allow-listed

        A resolved colour becomes an inline custom property, so a literal that could close a declaration would be a CSS injection. Validation happens once, server-side, against an anchored pattern.

        AcceptedRejected
        #fff, #ffff, #22c55e, #aabbccdd #12345 — not a valid CSS hex length
        rgb(), rgba(), hsl(), hsla() anything containing ; { }
        oklch(), lab(), lch(), color-mix() url( — the exfiltration vector
        var(--brand), var(--brand, #fff) expression(, image-set(, comments, backslashes

        Capped at 64 characters. The Vue component does no pattern matching at all — it binds a style object, which the browser parses and discards if unparseable.

        Rebranding a token

        Application tokens are resolved before the built-ins, so you can redefine success itself once rather than at forty call sites.

        config/nova-field-indicator.php
        'colors' => [
    'tokens' => [
        'brand'   => ['light' => 'violet-600', 'dark' => 'violet-400'],
        'success' => 'emerald-600',   // override a built-in
        'green'   => '#38C172',      // pin a 2.x colour exactly
    ],
],

          The package ships en and it. Keys are Unknown, Not set, Yes and No — the labels boolean() and unknown() produce in PHP.

              Security

              What the trust boundary actually is, and what it deliberately is not.

              Reporting

              Please report security issues to gabriele@sbaiz.com rather than opening a public issue.

              VersionSupported
              3.xYes
              2.xNo
              1.xNo

              Threat model

              This field renders a colour-coded mark. It never renders HTML, never uses v-html, and never echoes an attribute value as markup — so the usual stored-XSS surface of a Nova field does not apply.

              The one boundary that does exist is CSS, because a configured colour becomes an inline custom property.

              • Colour values are validated server-side against an anchored allow-list before they are serialized.
              • Anything containing ; { } /* \ < > url( expression( image-set( or javascript: is rejected with an exception.
              • The Vue component does no pattern matching on colours. It binds a style object, which Vue applies through setProperty(), so an unparseable value is dropped by the browser rather than concatenated into a declaration.
              This changed in 3.0. Version 2 classified colours in the browser with an unanchored regex and interpolated the result into a background:${color}; string. That would have accepted #fff; background-image:url(//example.com). Colour configuration normally comes from your own resource files rather than user input, so this is defence in depth rather than a live exploit path — it is enforced anyway, and the payloads are covered in tests/ColorResolverTest.php.

              Nova credentials

              auth.json holds your Nova licence credentials. It is listed in .gitignore and marked export-ignore in .gitattributes, so it is neither committed nor shipped in a distributed tarball. If you fork the package, verify both before pushing.

                Upgrading from 2.x

                A clean break, with a command that does most of it for you.

                Start here

                Terminal
                composer require gabrielesbaiz/nova-field-indicator:^3.0
php artisan nova-field-indicator:upgrade --dry-run

                Review the output, then run it without the flag. It is idempotent, so running it twice is safe — but commit first, because it rewrites files in place.

                It rewrites what is mechanical and reports what needs a human. Read that report: the first entry in it is the one that can bite silently.

                1. Four colours were invisible and now appear

                This is the reason 3.0 exists, and it is a fix that reads as a change.

                In 2.x, success, danger, warning and info were styled as var(--success) and friends. Those CSS variables existed in Nova 3 and 4. Nova 5 does not define them, so the mark painted with an invalid colour and rendered completely transparent.

                2.x on Nova 5

                Active Banned

                The marks above are genuinely there — and genuinely invisible.

                3.0

                Active Banned

                No opt-out, and there should not be one.

                2. Every named colour shifts hue

                2.x hard-coded the Tailwind v1 palette. 3.0 resolves to Nova’s, which is Tailwind 3.

                Name2.x3.0Change
                grey / gray#B8C2CCgray-400cooler, darker
                black#22292Fgray-900darker
                red#E3342Fred-500lighter, less orange
                orange#F6993Forange-500more saturated
                yellow#FFED4Ayellow-500noticeably darker
                green#38C172green-500similar
                teal#4DC0B5teal-500more saturated
                blue#3490DCblue-500more violet
                indigo#6574CDindigo-500similar
                purple#9561E2purple-500similar
                pink#F66D9Bpink-500more saturated

                The upgrade command rewrites any of these hexes it finds in a colors() call. To keep an exact old value, pass a literal, or pin the token once in the published config.

                3. Custom .indicator-* CSS stops applying

                2.x invited this, because colours were class names — .indicator-brand { background: #123456 } in your stylesheet, then ->colors(['active' => 'brand']).

                3.0 emits no indicator-* class at all, so those rules are dead and the value falls back to neutral grey. This is the sharpest real break in the release, and it is deliberate: keeping a legacy hook class would re-create exactly the stylesheet-source-order fragility being removed.

                Migrate in one line
                ->colors(['active' => '#123456']),

                4. Renamed and removed methods

                2.x3.0
                shouldHide($x)hideWhen($x)
                shouldHideIfNo()hideWhenEmpty()
                withoutLabels()removed — see below
                public $hideCallbackinternal
                $showOnCreation / $showOnUpdateimplicit

                There are no deprecation shims. A missed call site raises BadMethodCallException, which is a better failure than a silently wrong one.

                5. withoutLabels() is gone — read this one carefully

                The names are one character apart and the meanings are nearly opposite, so it is worth being explicit.

                2.x withoutLabels() meant “print the raw value instead of a mapped label”. In 3.0 that is simply the default: an unmapped value falls back to itself. In almost every case you just delete the call, and the command does that for you when the chain has no labels().

                3.0 withoutLabel(), singular, is a different feature: render the mark with no text at all. Reach for it only if that is genuinely what you want.

                If you had both withoutLabels() and labels() on one chain, the command refuses to guess and flags it — that combination was contradictory in 2.x, since the labels were ignored.

                6. A string is no longer a possible callback

                The one silent change
                // 2.x: is_callable('trim') was true, so trim() was INVOKED as the predicate.
// 3.0: 'trim' is a value, compared against the attribute.
->hideWhen('trim')

// If you wanted the callback:
->hideWhen(fn ($value) => trim($value) === '')

                The command reports every shouldHide() whose argument names a real PHP function. Scalar comparison is otherwise unchanged: both sides are normalised first, so 0 still matches '0' the way it did under 2.x’s ==.

                7. The field is read-only on forms

                It implements Unfillable and calls exceptOnForms(), so it is hidden on create, update, attach and update-attached — the last two of which the old $showOnCreation/$showOnUpdate pair missed. The 2.x form component was registered and bundled but unreachable and never wrote a value, so nothing can regress.

                Pair it with a real input
                Select::make('Status')->options($options)->onlyOnForms(),
NovaFieldIndicator::make('Status')->enum(Status::class),

                8. The payload changed

                Only relevant if you read the serialized field from the API or wrote your own Vue override. labels, colors, unknownLabel, withoutLabels are gone, replaced by an indicators list. The component is renamed from indicator-field to nova-field-indicator, and the asset handles from indicator to the same.

                Build output paths are unchanged — dist/js/field.js and dist/css/field.css — so there is no cache-busting step to worry about and nothing to republish.

                Subclasses that override resolveForDisplay() should override resolveIndicatorFor() instead; resolution moved to jsonSerialize().

                  Fixed

                  • success, danger, warning and info rendered an invisible dot on Nova 5. They were styled as var(--success) and friends — variables Nova 3 and 4 defined and Nova 5 does not. If you used these tokens, dots will now appear where your index looked empty.
                  • shouldHide('trim') silently invoked trim() instead of comparing against the string, because is_callable() was tested before the value branch.
                  • Colour literals are now validated server-side against an anchored allow-list before they reach an inline style.
                  • whitespace-no-wrap was Tailwind v1 syntax and had done nothing since Nova 4.
                  • The neutral colour no longer depends on stylesheet source order.
                  • Dark mode is supported at all, for the first time.
                  • The generic indicator asset handle, which any other package could collide with.

                  Added

                  • ->enum(Status::class) derives labels, colours and icons from one enum. A value that is a backed enum self-describes with no configuration at all.
                  • ->states(), shapes, three sizes, icons, ->ranges(), ->boolean(), the four closure resolvers, and ->pulse().
                  • ->filterable(): the field implements FilterableField and builds its own select-filter options.
                  • Accessibility: the mark is decorative when a label is visible and becomes a named role="img" when colour alone carries the meaning. Forced-colors mode is handled.
                  • Arbitrary Tailwind palette colours, light/dark pairs, and literal CSS colours as first-class values.
                  • A publishable config file, including a colors.tokens table for rebranding a token once.
                  • English and Italian translations.
                  • php artisan nova-field-indicator:upgrade.
                  • Real test coverage: 163 Pest tests and 17 Vitest tests, PHPStan level 6.

                  Changed

                  • Labels and colours are resolved on the server. 2.x pushed the whole configuration into every row of an index; the payload now carries one resolved indicator per value.
                  • Colours resolve to Nova’s own --colors-* variables. The built-in names now match the Tailwind 3 palette.
                  • The field is Unfillable and hidden on every form view.
                  • Vite 6 replaces Laravel Mix. Output paths are unchanged.
                  • The Vue component is now nova-field-indicator.
                  • The bundle is 1.09 kB gzipped, down from 1.4 kB, despite the added features.

                  Removed

                  • shouldHide(), shouldHideIfNo() and withoutLabels() — see Upgrading.
                  • The .indicator-* CSS classes.
                  • The FormField component, which was registered and bundled but unreachable.
                  • spatie/laravel-package-tools, which was required but never used.
                  • Fifteen npm dependencies, six of them copy-pasted from nova-field-map and never referenced.
